# 05 · 三次证据跳跃的复盘

这一篇是本仓库最值得读的部分。

同一个项目在早期得出过"网络层走不通"的结论，**结论碰巧是对的，
但支撑它的三条理据全部是错的**。下面记录它们，因为这类错误比结论错误更危险：
结论错了可以被新证据纠正，推理方式错了会一直产生新错误。

---

## 案例 1：把"按名字导入"当成"全部导入"

### 当时的推理

> 解析了主程序的全部 617 个导入项，`WS2_32.dll` 里只有 14 个函数，
> 其中没有 `WSASend` / `WSASendTo` / `sendto`。
> 因此主程序没有发包能力，对局流量只能由某个网络库发出。

### 实际

```
实际导入总数        673（不是 617）
WS2_32.dll 导入     43（不是 14）
其中按序号导入      29
```

这 29 个序号里包括：

```
ord  2  bind          ord 16  recv        ord 21  setsockopt
ord  3  closesocket   ord 17  recvfrom    ord 22  shutdown
ord  4  connect       ord 18  select      ord 23  socket
ord 19  send          ord 20  sendto      ord 13  listen
ord  1  accept        ord  6  getsockname
```

### 根因

Windows 的 `ws2_32.lib` 把 BSD 风格的核心函数**按序号导出**，
MSVC 链接后导入表里只有序号、没有名字。

任何只按名字扫描导入表的工具，都会在一个正常使用 WinSock 的程序上
得出"没有发包函数"的结论。

### 教训

**"没找到"不等于"不存在"，除非你证明了搜索方法能覆盖全空间。**
在写下"全部 N 个"之前，先确认你的枚举方式和链接器的编码方式一致。

`tools/pe_tools.py` 就是为此写的：它会反解序号。

## 案例 2：把"高熵"当成"强加密且密钥不可恢复"

### 当时的推理

> 对局流前 32 个字节位置的熵都是 7.99，首 4 字节唯一性 99.6%。
> 因此是强加密；再结合"临时密钥交换 + 私钥即用即焚"，
> 得出结论：抓包拿到的一切加起来也推不出会话密钥。

### 实际

- 算法确实是 AEAD，但**密钥根本不来自通道内的协商**，
  而是建立连接时由后端下发的一个 16 字节值
- 熵 7.99 是 AEAD 密文的正常外观，区分不了算法、更推不出密钥来源
- "临时密钥交换、私钥即焚"这一段来自对另一套网络库源码的阅读，
  与实际的加密层没有关系

### 根因

**把一个统计现象当成了结构性证明，然后在其上叠加了未经验证的假设。**

熵只能回答"看起来像不像随机"，回答不了"密钥从哪来"。

### 教训

统计量只能否证，不能证明。要用熵去支持一个关于**机制**的结论，
中间必须补上机制本身的证据。

## 案例 3：把"没扫到某种协议特征"当成"没有握手"

### 当时的推理

> 全量扫描了 DTLS 记录头特征，命中率与随机期望一致。
> 因此不是 DTLS，因此是"别的加密"。

### 实际

- 对局通道的密钥确实与 DTLS 有关（明文遥测里明确出现
  `dtls...session` / `dtls...new_key` 事件）
- 但扫描本身只覆盖了"载荷偏移 0 处的标准 DTLS 记录头"，
  而握手被外层加密了
- 真正的密钥下发发生在 TLS 会话里，不在 UDP 上

### 根因

**扫描的结论范围被写大了。** "这个位置没有这种特征"被写成了
"这个协议不存在"。

### 教训

每次写否定结论时，把它的**覆盖范围**一起写下来：

```
❌ 不是 DTLS
✅ 在 UDP 载荷偏移 0~8、以标准 DTLS 记录头为特征、对全部 N 个包的扫描中，
   命中数与随机期望无显著差异
```

第二种写法在后续被推翻时，能立刻定位是哪一步错了。

---

## 三条的共同点

```
"排除了一种可能"  →  写成  →  "证明了唯一解"
```

这是逆向工作里最自然的滑坡，因为每一步单独看都成立，
连起来就成了一个封闭的、无法自我纠正的结论。

## 防御办法

1. **结论分級**：已实测 / 已推断 / 未验证，三者分开放
2. **否定结论必须带范围**：在什么样本、什么方法、什么阈值下不成立
3. **方法先自证**：在用它判断真实数据前，先喂一个已知正确的输入，
   看它能不能识别出来
4. **换人复核**：同一份材料由不同视角重读，最容易发现滑坡

本仓库的 `docs/04` 就是按第 1 条写的：每一条都注明"实测"而不是"推断"。
